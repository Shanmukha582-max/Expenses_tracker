## Description
Expense Tracker is a mobile app built with Flutter for people who want a simple way to record daily spending. The user adds each expense with an amount, category, date and optional note, then sees all expenses in a list, opens a detail screen, and views the total spent per category. The app works offline: all data stays on the phone, so no internet, login or API key is needed.

## Features (mandatory scope)
- Add an expense through a validated form (amount, category, date, note)
- List of all expenses, newest first, with an empty state message
- Detail screen with edit and delete (delete asks for confirmation)
- Detail screen with the profile, theme, about us, backup and restore and one more.
- Summary screen with total spent and total per category
- Data saved on the device, still there after restart

## Technology stack
| Need | Choice | Why |
|---|---|---|
| Framework | Flutter (Dart) | One codebase for a native Android app; the screen is built from widgets |
| State management | Provider (`provider`) | A `ChangeNotifier` holds the data and calls `notifyListeners()`, so every screen watching it rebuilds |
| Local storage | SQLite (`sqflite`, `path`) | A database file on the phone supporting insert, read, update, delete |
| Date formatting | `intl` | `DateFormat` shows readable dates |

## Data source
All data is saved on the device using SQLite (sqflite). No external API. 

## Architecture and folder structure
The app has layers: **UI** (screens, widgets) -> **Provider** (state) -> **Database helper** (SQLite) -> **Model**. When the user presses Save, the screen calls `provider.addExpense()`, the provider writes to SQLite and calls `notifyListeners()`, and the list and summary both rebuild. This keeps the summary equal to the list.

```
lib/
  main.dart                     theme, routes, bottom navigation   (C)
  models/expense.dart           Expense class                       (A)
  services/db_helper.dart       SQLite create/read/update/delete    (A)
  providers/expense_provider.dart  state + totals per category      (A)
  screens/expense_list_screen.dart, add_expense_screen.dart,
          expense_detail_screen.dart                                (B)
  screens/summary_screen.dart                                       (C)
  widgets/expense_tile.dart                                         (B)
```

## Data model and validation
| Field | Type | Rule |
|---|---|---|
| id | int | Generated by the database |
| amount | double | Required, greater than 0 (empty, 0, negative, text rejected) |
| category | String | Required, from Food, Transport, Shopping, Bills, Other |
| date | DateTime | Required, chosen with a date picker, not in the future |
| note | String | Optional, up to 100 characters |

## Screens and navigation
The list is the home screen; a bottom bar switches between List and Summary. Flow: List -> (+) Add -> back to List; List -> tap row -> Detail -> Edit or Delete; Bottom bar -> Summary.  Navigation uses `Navigator.push` and `Navigator.pop`.

## Key concepts used (theory)
- **Form validation:** a `Form` with a `GlobalKey<FormState>`; each `TextFormField` has a `validator` that returns `null` if valid or an error message shown under the field. `DropdownButtonFormField` handles the category and `showDatePicker` (with `lastDate` = today) blocks future dates. The Save button is disabled until the form is valid. The same screen is reused for editing.
- **List and empty state:** `ListView.builder` builds only visible rows; when the list is empty a friendly message is shown instead.
- **Detail screen:** reads the expense from the provider by id, so it shows the latest values after an edit; delete uses an `AlertDialog` for confirmation.
- **Provider:** `context.watch` rebuilds a widget when data changes; `context.read` calls a method once (for example in a button handler).
- **SQLite:** CRUD methods are `async`; the database file survives closing the app and restarting the phone.
